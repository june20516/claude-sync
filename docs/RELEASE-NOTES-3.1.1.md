# claude-sync 3.1.1

3.1.0의 실기기 스모크가 잡은 이식성 결함 하나를 고칩니다. **3.1.0을 쓰고 있다면 올리세요** —
그 버전에서는 파일 기준선이 조용히 만들어지지 않습니다.

## 무엇이 틀렸나

`/sync-backup` 10단계가 base 갱신 대상을 모으는 데 `mapfile`을 썼습니다. 그것은 bash 4+의
빌트인이라 **macOS 기본 bash(3.2)에도 zsh에도 없습니다.** 없는 셸에서는 그 줄이
`command not found`로 죽고 배열이 빈 채 남습니다. 다음 게이트가 그것을 0으로 읽어
`update_base.py`가 **아예 호출되지 않습니다.**

오류도 경고도 보고도 없습니다. 종료 코드는 0이고, 백업은 성공한 것처럼 끝납니다.
결과만 3.1.0이 고치려던 결함 ②로 되돌아갑니다 — 백업만 하는 기기에 파일 기준선이 영영
생기지 않고, 그래서 기준선 없는 파일이 매번 "어느 쪽이 앞선지 알 수 없음"으로 뜹니다.

## 무엇을 고쳤나

- `mapfile`을 `while read` 루프로 바꿨습니다. bash 3.2와 zsh 모두에서 돕니다.
- **그 블록을 실제로 실행해 재는 가드를 더했습니다.** 앞 판의 가드는 블록의 **텍스트**만
  대조했기 때문에 이 결함을 통과시켰습니다. 4단계의 `.syncignore` 블록에는 실행해서 재는
  가드가 이미 있었고 10단계에는 없었습니다 — 그 층을 닫았습니다.
- 릴리즈 노트 가드가 파일명을 리터럴로 박지 않고 버전에서 유도하도록 고쳤습니다.
- 실기기 체크리스트의 3-3에서 "파일 기준선 8개 불변"이 ②를 재지 못한다는 것을
  명시했습니다 — 그 8개는 앞 실행에서 이미 만들어져 있어 단정이 공허합니다.

## 영향

백업 문서의 형식은 바뀌지 않습니다. `SCHEMA_VERSION`(2)·`MIN_READER_VERSION`(3.0.0) 불변이라
3.0.0·3.1.0 기기와 섞여도 순서 제약이 없습니다.

3.1.0에서 백업을 이미 돌린 기기라면 레포와 로컬은 정상이고, **빠진 것은 그 기기의 파일
기준선뿐**입니다. 3.1.1로 올린 뒤 `/sync-backup`을 한 번 더 돌리면 채워집니다.

## 3.1.0에서 올릴 때

```
claude plugin marketplace update claude-sync && claude plugin update claude-sync
```

재시작 후 `/sync-backup`을 한 번 돌리세요. `~/.claude/.sync-state/base/` 아래에 파일별
기준선이 생겼는지 확인하면 됩니다.
