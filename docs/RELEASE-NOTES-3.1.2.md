# claude-sync 3.1.2

3.1.0의 실기기 스모크를 끝까지 돌면서 찾은 **거짓 문장 둘**을 고칩니다. 동작은 바뀌지
않습니다 — 사용자에게 나가는 말과 소스의 주석입니다.

## 무엇이 거짓이었나

**레포 문서의 구문이 깨졌을 때 스크립트가 여전히 "손으로 고쳐라"고 말했습니다.**
3.1.0이 세 `SKILL.md`의 여섯 줄에서 그 문장을 걷어냈지만, 정작 그 문장은 코어
(`lib/keyed_sync.py`)가 만드는 `reason`에도 있었습니다:

> `…이 문서를 건너뛴다. 파일을 정상 JSON으로 고친 뒤 다시 실행한다`

세 `SKILL.md`가 `reason`을 **그대로 보여주라**고 지시하므로, 산문을 고쳤어도 그 지시가
스크립트 메시지를 통해 사용자에게 그대로 도달했습니다. 2026-09-02 실기기 스모크에서
실제 출력으로 확인했습니다.

이제 코어는 **무슨 일이 있었는지만** 말합니다. 처방은 스킬이 냅니다 — 복구는
`/sync-backup` 4.5단계가 git 이력에서 마지막 정상 판본을 찾아 되돌릴지 묻는 것이고,
코어는 어느 스킬이 도는지 모릅니다. 바로 옆의 `UnknownBackupSchema`가 이미 그 형태였고
(사실만 말하고 "플러그인을 업데이트하라"는 `SKILL.md`에 있습니다) `broken_syntax`만
예외였습니다.

**10단계 주석이 "세 셸에서 모두 돈다"고 적었습니다.** 3.1.1이 `mapfile`을 `while read`로
바꾸면서 붙인 주석인데, POSIX `sh`는 프로세스 치환(`< <(…)`)이 없어 거짓입니다. 실제로
도는 것은 bash와 zsh 둘이고, 테스트도 그 둘로 재고 있었습니다 — 주석만 어긋났습니다.

## 재발 방지

두 자리 모두 **주장이 측정과 묶여 있지 않아서** 생긴 것입니다. `mapfile`을 놓친 것과
같은 형태입니다.

- 코어의 `reason`이 손 복구를 지시하지 않는지 재는 가드를 더했습니다. 금칙어 목록에
  **개수 단정**을 함께 걸어 목록이 스스로 줄어드는 것도 잡습니다.
- 10단계 주석이 주장하는 셸과 테스트가 실제로 파라미터화한 셸이 같은지 재는 가드를
  더했습니다.

## 영향

백업 문서의 형식은 바뀌지 않습니다. `SCHEMA_VERSION`(2)·`MIN_READER_VERSION`(3.0.0)
불변이라 3.0.0 이상 어느 버전과 섞여도 순서 제약이 없습니다.

## 3.1.1에서 올릴 때

```
claude plugin marketplace update claude-sync && claude plugin update claude-sync
```

재시작하면 끝입니다. 데이터에 영향이 없으므로 추가로 할 일이 없습니다.
