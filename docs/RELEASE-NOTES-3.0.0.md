# claude-sync 3.0.0

여러 기기의 Claude 설정을 Git 레포로 동기화하는 플러그인입니다. 이 릴리즈는 **백업 파일이
다른 기기의 내용을 지우던 결함 세 가지**를 닫고, MCP 서버를 실제로 복원할 수 있게 만듭니다.

---

## ⛔ 먼저 읽을 것 — 업그레이드 순서

3.0.0은 백업 파일의 형식이 바뀌는 **역호환되지 않는 릴리즈**입니다.

> **모든 기기를 3.0.0으로 올리고 재시작하기 전에는 어느 기기에서도 `/sync-backup`을
> 실행하지 마세요.**

2.x의 백업 단계는 레포를 읽지 않고 `plugins.json`과 `mcp-servers.json`을 **그 기기 것만으로
통째로 다시 만듭니다.** 한 번만 실행해도 다른 기기에만 있던 항목이 레포에서 사라지고,
2.x가 아예 모르는 `pluginConfigs`·`additionalMarketplaces`는 그 기기 것까지 사라집니다.
**MCP 서버를 하나도 쓰지 않아도 해당됩니다** — `plugins.json`이 같은 방식으로 무너집니다.

3.0.0은 이 사고를 **탐지하고 복구 후보를 제안할 수는 있지만 막지는 못합니다.** 2.x에는
표식을 읽는 코드가 없기 때문입니다. **실행 순서가 유일한 방어입니다.**

```bash
claude plugin marketplace update claude-sync
claude plugin update claude-sync    # 적용하려면 Claude Code 재시작
```

모든 기기가 올라간 것을 확인한 뒤 **순서를 지켜 실행합니다.**

1. **한 기기에서만 `/sync-backup`.** 이 한 번이 레포를 새 형식으로 옮깁니다.
2. **나머지 기기는 `/sync-restore`가 먼저입니다.** 그 기기에는 아직 비교 기준선이 없어
   양쪽에 있는 항목이 모두 "양쪽이 모두 바뀌었습니다"로 나오고 항목마다 묻습니다. 그것이
   선택을 지키는 장치입니다 — 한 번 답하면 기준선이 생겨 다음부터는 조용해집니다.

기준선이 없는 기기에서 백업을 먼저 하면 **묻지 않습니다.** 병합이 합집합으로 물러나면서
양쪽에 있는 항목을 그 기기의 값으로 덮고, **충돌로 보고하지 않습니다.** 삭제는 없지만
다른 곳에서 정해 둔 값이 조용히 바뀝니다. 3.0.0은 이 상태를 백업 직전에 **감지해서
물어봅니다.**

## 중요 — 데이터가 사라지던 자리 셋

**다른 기기의 항목이 더 이상 사라지지 않습니다.** 이전에는 백업이 파일을 통째로 다시 써서,
A 기기에서 백업하면 B 기기에만 있던 플러그인·MCP 서버가 레포에서 지워졌습니다. 이제 두
파일 모두 **항목 이름 단위로 3-way 병합**됩니다. 삭제는 여전히 전파되지만, 복원할 때
항목마다 물어봅니다.

**켜고 끈 것이 동기화됩니다.** 이전에는 이름 목록만 비교해서, 플러그인을 끈 변경이
"차이 없음"으로 보고됐습니다. 이제 값을 비교하며 어느 방향으로 바뀌었는지도 말합니다.

**읽지 못한 파일을 "0개"로 읽지 않습니다.** 레포 파일이 깨졌거나 상위 버전이 쓴 것이면
그 문서만 건너뛰고 레포도 기준선도 손대지 않습니다. 이전에는 읽기 실패가 "항목이 하나도
없다"로 해석돼, 다음 백업이 그 판단대로 레포를 비웠습니다.

## 새로 생긴 것

**MCP 서버가 실제로 복원됩니다.** 2.x는 `claude mcp list`의 출력 텍스트에서 이름·URL·타입만
긁어 저장했기 때문에 stdio 서버는 복원이 불가능했습니다. 이제 `~/.claude.json`의 user
스코프를 그대로 읽어, `headers`와 `env`의 **값만** `<REDACTED>`로 가리고 키 이름은 남깁니다.
복원할 때 어떤 비밀 값을 물어야 하는지 알기 위해서입니다.

**플러그인 설정과 마켓플레이스가 동기화 대상에 들어왔습니다.** `pluginConfigs`는 값을
마스킹하고 키 이름만 올립니다. 마켓플레이스 목록도 함께 옮겨집니다.

**버전 표식과 차단.** 백업에 "이 백업을 읽으려면 최소 몇 버전이 필요한지"가 기록됩니다.
낮은 버전 기기에서 `/sync-backup`은 차단되고, `/sync-status`는 경고만 하며,
`/sync-restore`는 계속할지 묻습니다. 진단 수단과 업데이트 안내 경로를 남겨 두려는
구분입니다. 이 표식 덕분에 다음 major 전환에서는 같은 사고가 반복되지 않습니다.

**다운그레이드 탐지.** 낮은 버전 기기가 레포를 옛 형식으로 되돌린 흔적을 git 이력에서
찾아, 마지막 정상 커밋을 복구 후보로 제시합니다. 자동으로 복구하지는 않습니다 — 옛 기기가
의도적으로 지운 항목까지 되살리기 때문입니다. 이 상태에서는 복원 화면의 문구도 바뀝니다:
"다른 기기가 삭제했습니다"가 아니라 "낮은 버전 기기가 되돌리면서 유실된 것으로 보입니다"로
말하고, 기본 선택을 "유지"로 둡니다.

**항목마다 묻습니다.** 삭제되거나 변경된 항목은 한 건씩 확인합니다 — 제거 / 유지 / 나중에,
또는 레포 값 채택 / 로컬 유지 / 나중에. 같은 세 선택지가 MCP 서버·플러그인·마켓플레이스·
설정 키에 똑같이 적용됩니다.

## 그 밖의 변경

- **`.syncignore`의 뜻을 하나로 못박았습니다** — "올리지 않는다", 백업 방향 전용입니다.
  백업은 그 경로를 레포에서 **지우고**(다른 기기가 올려 둔 같은 경로 사본도 함께),
  복원은 `.syncignore`를 읽지 않으며, `/sync-status`는 두 경우를 따로 보고합니다.
  gitignore 문법이 아닙니다 — 부정(`!`)이 없고 후행 슬래시는 매치가 0건입니다.
- **동기화하지 않는 것을 명시했습니다**: 마켓플레이스 자동 업데이트 설정, 로컬 디렉토리
  마켓플레이스와 그 소속 플러그인, 의존성으로 자동 설치된 플러그인, 명령으로 설치하는
  플러그인, 버전 제약(배열·객체) 값, 플러그인 설정 값.
- **실행할 스크립트를 고르는 방법을 고쳤습니다.** 이전에는 설치 캐시에서 임의의 버전이
  선택될 수 있어, 3.0.0 세션이 2.0.0 스크립트를 실행하는 일이 가능했습니다.
- 백업 레포에 `/*.tmp`를 무시하는 `.gitignore`가 생깁니다(새 기기 부트스트랩 시).
- **기준선이 없는 첫 백업을 감지해 물어봅니다.** 그 상태의 병합은 충돌 판정을 하지 못하고
  로컬 값으로 덮으므로, 덮을 상대가 레포에 실제로 있을 때만 확인을 받습니다.
- 테스트 99 → **1211**.

## 알려진 제약

- **2.x 기기를 막을 수 없습니다.** 실행 순서가 유일한 방어입니다.
- **버전 제약(배열·객체) 값은 재현되지 않습니다.** CLI에 그 값을 쓸 수단이 없어 레포 값을
  보존만 합니다. 포기하려면 복원 중 "이 기기 값으로 통일"을 고르세요.
- **MCP 비밀 값은 대화 기록에 남습니다.** `claude mcp add-json`이 JSON을 위치 인자로만
  받기 때문이며, 현재 CLI에 대안이 없습니다.
